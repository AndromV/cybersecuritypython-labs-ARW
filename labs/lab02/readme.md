## 3. Опис функціоналу завдань

### Завдання 1. Об'єктно-орієнтована модель безпеки (`task1.py`)
Реалізує архітектуру автентифікації та контролю доступу:
1. **Клас `User`:** Безпечне збереження паролів із використанням повільної хеш-функції `hashlib.pbkdf2_hmac` (`sha256`, 100 000 ітерацій, унікальна криптографічна сіль `os.urandom(16)`). Перевірка паролів через `hmac.compare_digest` (захист від *timing attacks*). Валідація електронної пошти через `@property` за допомогою регулярного виразу `re`.
2. **Клас `Admin` (Наслідування «Is-A»):** Успадковує `User`, розширює функціонал колекцією дозволів `permissions` (`grant_permission`, `revoke_permission`, `has_permission`).
3. **Клас `Session`:** Відстеження активності сесії в часовому поясі UTC (`datetime.now(timezone.utc)`), перевірка таймауту неактивності.
4. **Клас `AuditLog`:** Ведення системного журналу за допомогою структури даних `@dataclass AuditRecord` (`login_success`, `login_failure`, `logout`).
5. **Клас `UserAccount` (Композиція «Has-A»):** Агрегує `User`, `Session` та `AuditLog`. Контролює доступ до внутрішніх полів через спеціальні методи `__getitem__` та `__setitem__` (`KeyError`, `TypeError`).

### Завдання 2. Аудитор безпеки HTTP-заголовків (`task2.py`)
Здійснює перевірку відповідей веб-серверів на відповідність стандартам безпеки:
1. Парсинг структури `headers.json` за допомогою `json` та `pathlib`.
2. Перевірка наявності 4 критичних заголовків безпеки:
   * `Strict-Transport-Security` (HSTS)
   * `Content-Security-Policy` (CSP)
   * `X-Frame-Options`
   * `X-Content-Type-Options`
3. Виявлення витоку версій програмного забезпечення та технологічного стека у заголовках `Server` та `X-Powered-By` за допомогою регулярного виразу `\d+(?:\.\d+)+`.
4. Розрахунок підсумкового показника безпеки (Score: 0–100), літерного грейду (A+ ... F) та статусу (`PASS`, `WARN`, `FAIL`).
5. Експорт структурованого звіту у формат CSV та логування процесу за допомогою `logging`.

## 4. Інструкція із запуску програми

Усі модулі запускаються з кореня репозиторію через ключ `-m`:

### 4.1. Демонстрація Завдання 1 (`demo`)
Запуск демонстраційного сценарію роботи класів ООП:
```powershell
python -m labs.lab02.main demo
```
*Сценарій наочно демонструє:* створення користувача, невдалу та успішну спроби входу, валідацію зміни email, керування правами адміністратора, завершення сесії за таймаутом і фінальний вивід журналу аудиту `AuditLog`.

---

### 4.2. Аудит безпеки заголовків Завдання 2 (`analyze`)

#### Базовий запуск (типові налаштування):
```powershell
python -m labs.lab02.main analyze --headers-file labs/lab02/data/data_v09/headers.json
```
*(Підсумковий CSV-звіт буде автоматично збережено за шляхом `labs/lab02/data/headers_audit.csv`)*.

#### Запуск із явним зазначенням шляху до CSV-файлу:
```powershell
python -m labs.lab02.main analyze --headers-file labs/lab02/data/data_v09/headers.json --output-csv labs/lab02/data/headers_audit.csv
```

#### Запуск у суворому режимі (`--strict`):
```powershell
python -m labs.lab02.main analyze --headers-file labs/lab02/data/data_v09/headers.json --strict
```
*(У суворому режимі за наявності хоча б одного відсутнього заголовка або витоку версії статус ресурсу автоматично знижується до `FAIL`)*.

#### Запуск із розширеним рівнем налагодження (`DEBUG`):
```powershell
python -m labs.lab02.main analyze --headers-file labs/lab02/data/data_v09/headers.json --log-level DEBUG
```

#### Повний комбінований виклик (усі параметри разом):
```powershell
python -m labs.lab02.main analyze --headers-file labs/lab02/data/data_v09/headers.json --output-csv labs/lab02/data/headers_audit.csv --strict --log-level DEBUG
```

## 5. Опис параметрів командного рядка (CLI)

| Аргумент | Тип | Обов'язковий | Значення за замовчуванням | Опис |
| :--- | :--- | :---: | :--- | :--- |
| `command` | `str` | **Так** | — | Підкоманда: `demo` (Завдання 1) або `analyze` (Завдання 2). |
| `--headers-file` | `Path` | **Так** | — | Шлях до вхідного JSON-файлу з дампами HTTP-заголовків. |
| `--output-csv` | `Path` | Ні | `labs/lab02/data/headers_audit.csv` | Шлях для збереження підсумкового звіту перевірки у форматі CSV. |
| `--strict` | Прапорець | Ні | `False` | Вмикає суворий режим аудиту (безкомпромісний `FAIL` за будь-яких порушень). |
| `--log-level` | `str` | Ні | `INFO` | Рівень логування: `DEBUG`, `INFO`, `WARNING`, `ERROR`. |

Отримання вбудованої довідки:
```powershell
# Загальна довідка
python -m labs.lab02.main --help

# Довідка за аргументами команди analyze
python -m labs.lab02.main analyze --help
```

## 6. Поведінка програми при помилках та виняткових ситуаціях

Утиліта реалізує надійну обробку винятків за принципом захисного програмування:

1. **Відсутність або неправильний шлях до вхідного файлу:**  
   Якщо вказаний файл не існує, виникає `FileNotFoundError` (або `OSError`). Програма перехоплює помилку, виводить повідомлення в потік помилок `stderr` (`Помилка під час аналізу: Файл вхідних даних не знайдено: ...`) та коректно завершує роботу з кодом завершення `sys.exit(1)`.
2. **Пошкоджений або некоректний JSON:**  
   У разі синтаксичних помилок у файлі (`json.JSONDecodeError`) програма не падає аварійним трейсом, а повідомляє про невалідний формат даних.
3. **Невідповідність структури даних:**  
   Якщо кореневий елемент JSON не є списком або об'єкт містить некоректні типи, викидаються винятки `ValueError` / `TypeError`, які перехоплюються обробником верхнього рівня.
4. **Помилки аргументів CLI:**  
   Модуль `argparse` автоматично валідує вхідні прапорці. Якщо пропущено `--headers-file` або вказано недопустимий `--log-level`, користувач отримує системне пояснення помилки та короткий синтаксичний довідник.
